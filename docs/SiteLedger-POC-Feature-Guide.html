THE POC AT A GLANCE

Built around the way construction work moves.

SiteLedger demonstrates how a construction company could follow a customer relationship from its first enquiry through estimating, project delivery, payment and handover—without switching between disconnected views.

Business visibility

An owner can scan active work, delivery risks, open pipeline, follow-ups and receivables on one executive dashboard. KPI values are calculated from shared records rather than separately hard-coded totals.

Stable IDs link leads, customers, projects, tasks, quotes, variations, invoices, email conversations, calendar events and activity. Related records can be followed across modules.

03 · Commercials & finance
CONTROL THE COMMERCIAL DETAIL

Make decisions and balances easy to follow.

Quotes, variations, invoices and supplier bills share project/customer links and use reusable calculations so the same figure can be reviewed in multiple screens.

▤

Quotes

Track references, descriptions, customer/project, amount, created/sent/expiry dates, follow-up and status from draft through acceptance or decline. Update statuses locally and open quote details.

＋

Variations

Track requested value, schedule impact, request date and approval. Approved values are summed against the original contract. Changing a variation back to a non-approved state removes it from the revised total.

Revised contract = original contract + approved variation amounts.

The application calculates the approved set from the source records, so each variation is counted once rather than repeatedly added when its status changes.

Finance workspace

Invoices

Search and filter by status, project and customer. Review issue/due dates, amount, paid amount, outstanding balance and payment breakdown. A “mark paid” action updates only the local demo record.

Supplier bills

Switch to bills to review supplier, linked project, dates, amount paid, outstanding balance and status.

CalculationRule used in the POC
Open pipelineSum estimated lead values, excluding Won and Lost.
Outstanding balanceMaximum of zero and invoice amount less amount paid.
Overdue receivablesInvoice due date is before today and outstanding balance is greater than zero.
Invoice ageingCurrent, 1–30, 31–60 and 61+ days overdue; fully paid invoices are excluded.
Budget varianceActual cost minus budget. A positive value means actual cost exceeds budget.
Finance is illustrative—not accounting.

The Finance page identifies sample data and states Xero is not connected. No invoice is issued, no payment is processed, and no accounting record is changed externally.

04 · Communications, reports & integrations
FROM DAILY WORK TO BUSINESS INSIGHT

Bring the operational picture together.

The remaining modules show how communications, reporting and future system connections could fit into the same workflow—while making the demo boundary explicit.

✉

Communications

  • Search mock conversations and filter by customer, project, unread or follow-up.
  • Open message details, mark read/unread and flag/unflag for follow-up.
  • Review a calendar agenda of meetings, inspections and site events.
  • Compose and save a local draft; the UI confirms that it has not been sent.
▥

Reports & analytics

  • Lead count and pipeline value by stage; lead sources and sales outcomes.
  • Project status/health, task status and overdue milestones.
  • Sample receivables, ageing, bills and budget-versus-actual views.
  • Project/date filters recalculate selected charts; CSV export downloads current project data.

Simulate sync is deliberately local.

A click changes the displayed simulated-sync timestamp and adds a row to mock sync history, including the sample warning. It does not connect to a provider, fetch records, or change the disconnected state.

Settings

Configure company/user display names, currency and demo notification preference. Currency formatting is shared throughout the application. Reset restores the seed records while preserving workspace preferences.

Global search

Search leads, customers, projects, invoices and quotes from the top bar. Results show record type and a secondary description; selecting a result opens its module. Ctrl/⌘+K focuses search.

05 · Demo operation & next steps
HOW TO EVALUATE THE DEMONSTRATION

Explore safely. Learn what to build next.

The POC is designed for stakeholder walkthroughs and workflow feedback. It demonstrates front-end behavior only and should not be used to manage live construction, customer or accounting data.

Local data behavior

Seed records initialize on first use. Changes persist in browser local storage for that browser/profile. Records are fictional. Reset restores seeded records, and invalid saved JSON falls back to fresh seed data.

Run the application

Install Node.js 18 or later, then run npm install and npm run dev from the project folder. Create a production build with npm run build.

Scope boundaries

  • No backend, API server or database.
  • No authentication or authorization.
  • No live Buildxact, Xero or Microsoft Graph connections.
  • No email sending, invoice issuing or payment processing.
  • No document upload/storage; register is metadata only.
  • No cross-device synchronization or shared users.
  • Financial, customer and operational records are fictional.
  • Light theme only; other selected theme values are preferences only.
Recommended next step: validate the workflow before integrating.

Use stakeholder sessions to confirm ownership, status definitions, approval rules, reporting needs and the authoritative system for each data domain.

1 · Product discovery

Confirm personas, permissions, field requirements and exception paths.

2 · Data & security

Design backend, audit, access control, privacy and retention before real data.

3 · Integration design

Validate vendor APIs, system-of-record ownership, reconciliation and failure handling.
